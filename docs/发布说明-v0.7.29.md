# Serylane v0.7.29

## 路由开启与状态核验

- 修复编辑路由设置后顶部与页内开启入口同时被禁用的问题。缺少出口或尚未保存时，按钮引导到路由页的对应操作；编辑恢复原值后正确解除待保存状态。
- 保持路由默认关闭。用户明确选择出口并保存草稿后，再独立确认开启；保存不启用，不自动切换系统代理、TUN、订阅或 AI/自选节点模式。
- 路由应用使用真实核心回读：核对运行模式、规则总数和前置域名规则的顺序、匹配内容与目标。核对通过才显示已生效；等待核心、规则不一致、读取异常分开展示。已启用但核对异常时提供重新应用入口。
- 对其他配置操作短暂占用增加有界等待；保留修订与配置身份检查。加载、验收或落盘失败走原事务回退，并核验回退后的核心状态；失败保留编辑，不盲目重试结果不明的写入。
- 路由错误展示具体的脱敏原因；日志记录操作 ID、阶段、结果和耗时，不记录订阅凭据或原始配置。

## 测试与支持范围

- 增加真实隔离 Mihomo 测试：保存不生效、开启、关闭、子域通配、根域与相似域不误匹配、非名单规则保留、模式不一致、加载/落盘失败、配置变化回退、重启及缺失出口。
- 复用生产配置编译器、事务协调器、存储与核心 API；另覆盖成功响应但规则错误、回退核验失败、双入口交互和并发操作。真实核心专项成为普通 Rust 测试的一部分，在六个平台执行，不以合成 UI 状态代替核心验收。
- 本轮不新增 Codex 接入，不恢复程序代理或增强灾备，不修改现有更新签名及安装流程。macOS 仍采用兼容包发行，Developer ID、公证和 TUN 支持范围保持原状。
- 核对只证明核心规则已加载，不代表第三方账户、模型会话或全部既有连接已切换；仅处理进入核心的新连接，不主动断开用户连接。
