# 代理质量验收

本方案覆盖 Windows 系统代理、TUN、AI 分流和 Codex 长连接。优秀线是 Serylane 的验收目标。IETF 规范和 OpenAI 文档规定协议判定条件。成功率、延迟、恢复时间和成本目标由项目定义。 [WebSocket 握手规范](https://www.rfc-editor.org/rfc/rfc6455.html#section-4.1) · [HTTP/2 Extended CONNECT](https://www.rfc-editor.org/rfc/rfc8441.html#section-5) · [OpenAI 流式兼容要求](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility#streaming) · [SLO 测量方法](https://sre.google/workbook/implementing-slos/)

## 十项优秀线

| 指标 | 优秀线 | 观测口径 |
| --- | --- | --- |
| 冷启动就绪 | P95 ≤ 2,000 ms | 从发出启动指令到控制器可读且受控请求在预期出口成功。记录启动超时。Windows 系统代理、TUN 分别测试。 |
| 系统状态恢复 | 扩展矩阵 100% 在 3,000 ms 内正确 | 正常停止、启动失败、崩溃后恢复、第三方接管分别核对代理、PAC、绕过和应用拥有的网络状态。 |
| 分流正确率 | 扩展矩阵 100%，禁止直连的请求零绕行 | 用 IPv4、IPv6、DNS、进程、规则冲突、拒绝及故障的预期结果，对照实际链路和服务端出口。 |
| WSS 首次握手 | 10 秒内成功率 ≥ 99.9% | 只统计新建连接的首个握手。HTTP/1.1 核对 `101` 和协议头，HTTP/2 按 Extended CONNECT 判定。回退结果独立记录。 |
| 模型流完整完成率 | ≥ 99.9% | 已开始的模型流须收到匹配的成功终态。分别报告首事件前失败、主动取消、每次重试和整个任务终态。 |
| 首文本附加延迟 | 配对差值 P95 ≤ 100 ms | 同目标、传输和负载交替测候选、对照。首个非空文本增量为结束点，候选减对照，负差值取零。 |
| 意外断开密度 | ≤ 0.5 次／百连接小时 | 按连接 ID 记录已建立的累计小时和意外结束。主动关闭或确认的计划关闭单列。 |
| 故障恢复 | P95 ≤ 30,000 ms | 从故障实际生效，到经核验备用出口的成功新流收到首事件。它须在 180 秒观察窗内完整结束。未恢复记录保留。 |
| 健康出口误切 | 连续 72 小时观察到 0 次 | 对照原出口健康证据和自动切换原因。手动、策略、预算变更和无法归因的切换分别记录。 |
| 单位成功任务折算流量 | ≤ 同负载健康对照的 1.10 倍 | 将所有尝试含失败和重试的上下行字节按核实倍率折算，再除以成功任务数。后台探针独立记录。 |

持续测试使用同一时钟和独立的试验编号。把系统代理与 TUN、新建与复用、WSS 与 SSE、合成与真实负载分别采样。报告分母和未知样本，保留失败及超时。用独立零失败样本证明 99.9% 成功率，在单侧 95% 置信水平下约需 2,995 次。具有共同断网窗口的重试不视为独立样本。

## 竞品对照

以 Clash Verge Rev v2.5.10 为参考。分别测产品默认配置和相同 Mihomo 版本、规则、节点及网络的控制组。Windows 试验从同一隔离镜像恢复，交替运行两款应用。 [固定版本](https://github.com/clash-verge-rev/clash-verge-rev/releases/tag/v2.5.10)

| 可测属性 | 验收步骤 |
| --- | --- |
| 开关可信 | 预设 PAC 和第三方代理，模拟端口占用和快速切换。记录界面与系统一致率、就绪时间和恢复正确率。 |
| TUN 就绪可信 | 分别用遵循和忽略系统代理的客户端访问受控目标，验证网卡、路由、DNS、服务端出口与界面结果。 |
| 分流可解释 | 匹配试验 ID、Mihomo 规则与实际出口，记录符合真值表和证据完整的比例。 |
| 坏配置可恢复 | 用有效配置、HTTP 403、超时和无效 YAML 验证原有效配置、用量采样和既有连接。 |
| 切换可预测 | 隔离断开主出口，统计新流恢复和已确认在健康线路上的既有流保留情况。 |

连接证据可用 Mihomo 控制器的只读连接接口与受控服务器交叉验证。冷建连用 k6 或客户端握手观测。系统接管、TUN 故障注入和状态恢复在隔离镜像执行。 [Mihomo 连接 API](https://wiki.metacubex.one/en/api/#connections) · [k6 WebSocket 测试](https://grafana.com/docs/k6/latest/examples/websockets/)

## 测量仪与证据边界

```text
npm run test:quality
node scripts/proxy-quality.mjs --fixture
node scripts/proxy-quality.mjs evaluate trial.ndjson
node scripts/proxy-quality.mjs evaluate trial.ndjson --require-excellent
```

输入定义见[测量仪使用说明](../scripts/proxy-quality.md)。报告逐项显示达标、未达标、证据不足或缺失。CI 和发布前检查使用隔离样例验证计算和保护条件。实际环境成绩使用同范围的现场数据。

验收防止把 401 当模型成功、把 HTTP 200 或 EOF 当终止、把 HTTP 回退当 WSS 握手、把界面开关当实际出口、用短测速代替长流、用平均值掩盖尾延迟、用重试掩盖首发失败、用时间邻近给节点归因、用瞬时波动触发切换，或把未知倍率当作 1×。日志和控制器快照无法逐条关联时，真实流和出口保留为未知。普通加密系统代理可提供连接级证据，真实模型流终态须由独立的受控采集提供。

此版本不包含用户当前机器或竞品的真实成绩。正式发布、平台原生测试和真实网络验收各自保留证据。
