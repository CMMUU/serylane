# Serylane v0.7.45

## macOS TUN

- macOS 完整安装包使用 **Developer ID 签名、Hardened Runtime 和 Apple 公证**。请在[下载中心](https://downloads.cmmuu.com/projects/serylane)选择 **Apple 芯片（M 系列，ARM64）**或 **Intel 芯片（x64）**的对应安装包。v0.7.44 等历史临时签名兼容包仍不满足 TUN 要求。
- 修复升级后 launchd 仍尝试按旧登记启动辅助程序、返回 `78: EX_CONFIG` 的问题。仅对确认启动失败的旧登记尝试一次重关联，等待旧服务退出并移除，再验证新版辅助程序的签名身份、版本和协议。网络模式与原有恢复偏好不因重关联而更改。
- 从兼容包升级时，如 macOS 再次要求后台服务许可，在「系统设置 → 通用 → 登录项与扩展」允许 Serylane，然后重新打开应用。看到辅助服务就绪后再开启 TUN。首次使用仍需在应用设置中安装辅助服务，并完成系统授权。

## 验收范围

已在同一台 Apple 芯片 Mac 的隔离 macOS 27.2.1（26B131）虚拟机中，使用已公证候选重现旧登记故障。确认新版辅助程序就绪后，未配置 HTTP 代理的 TCP 和外部 IPv4 HTTPS 实际通过 `utun4`；点击「停止」后，Mihomo 退出，路由与系统代理恢复到测试前状态。宿主的代理和默认路由保持不变。

Intel 工件的签名、公证及安装升级检查与 TUN 数据面实测分开记录；本轮实网测试不覆盖 Intel 实机、休眠唤醒、IPv6 或模型长流。Windows TUN 仍为需要管理员权限的实验性功能；Linux 尚未实现 TUN 接管。应用内更新路径和域名路由规则不变。
