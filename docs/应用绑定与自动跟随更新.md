# 应用绑定与自动跟随更新

[返回文档索引](index.md) · [v0.7.12 发布说明](发布说明-v0.7.12.md)

## 使用方法

Windows 的「程序代理」提供两个入口：从已安装应用选择（MSIX / Store）和选择普通 `.exe`（包括便携软件）。选择应用、设置代理方式后保存，再明确点击「代理启动」。保存和刷新均不启动程序，不切换系统代理或 TUN。

应用绑定保存包系列标识与清单 Application Id，不保存版本目录作为身份。正常升级保持该身份时，刷新清单和启动前都从当前用户的 Windows 注册信息重新解析入口；不扫描 WindowsApps 并挑选最大版本目录。自动跟随已安装版本不承担下载或安装更新。

名称与当前安装版本在卡片显示，完整路径和应用标识收进详情。区分未安装、系统更新中、维护中、需要重新关联、入口文件缺失、启动方式待适配和读取失败。单纯文件缺失不推断为更新。

## 参数、工作目录与迁移

代理方式与逐项启动参数独立于应用身份保存。工作目录支持：跟随当前入口目录、自定义绝对路径、包内相对目录（`.` 代表包目录）。自定义项目目录不会被替换成安装目录。

首次写入 v2 清单前保留原始 `proxy-programs.v1.backup.json`。旧条目仅在可执行路径与当前注册应用入口唯一、精确匹配时自动绑定，保持原 ID、名称、参数和代理方式。确定在包目录内的工作目录转为相对目录，其余原样保留。旧版本已经被移除、身份变化或匹配不唯一时，使用「重新关联」，原参数继续保留；请选择后检查工作目录并保存。旧版应用只认识 v1，降级前需停止编辑并自行从备份恢复，不用新清单覆盖备份。

## 实现与启动边界

Windows 原生 PackageManager 查询当前用户的 Main 包，读取清单入口及应用显示信息；安装/更新/移除事件使 30 秒缓存失效，启动始终强制重新查询。WinRT 在单个延迟启动的 MTA 工作线程执行，队列有界、调用等待上限为 12 秒；这些查询不占用全局配置锁，也不加入系统代理启动链路。

打包桌面应用继续通过受控子进程启动，设置子进程代理变量；Chromium 模式另加代理参数。需要系统激活、宿主或清单专用参数的应用标记为待适配，不静默改为普通启动。启动前以应用/包身份及可执行路径核对后台实例，覆盖旧版本仍在运行的情况。不结束已有进程，不改全局环境变量。

仅在确定创建进程失败且文件消失时重新解析并重试一次；成功或结果不确定的启动不重复执行。已发起启动不等于全部流量已走代理，也不等于真实 Codex 长会话已验证。

## 验证分层

- 跨平台单元测试：版本路径变化、身份变化、同包多入口、多版本歧义、读取失败、相对目录边界、旧数据备份和参数保留。
- Windows 原生测试：实际 WinRT 枚举、XML 清单解析、已有进程身份查询。
- `scripts/test-windows-app-binding.ps1`：仅在本仓库一次性 GitHub 托管 Windows runner 上签名、安装临时 MSIX，先 v1 再 v2；按同一身份解析当前安装入口，确认子进程保留包身份并收到代理环境变量，不弹控制台。测试结束卸载临时包并移除本次证书，不修改开发模式；拒绝在用户日用电脑执行。松散开发目录注册不代替真实安装包身份验收。
- 浏览器 fixture：已安装应用搜索、添加、更新版本展示、异常提示、重新关联、原参数和普通文件入口。全为合成状态，不读本机真实安装列表。
- 真实 Codex 应用升级、实际网络请求与长会话为单独实机验收，未以 fixture 或交叉编译替代。
