# Serylane v0.7.35

## TUN DNS 配置兼容

修复订阅关闭内置 DNS 时，应用开启 TUN DNS 劫持却没有相应解析服务的问题。仅调整生成的 TUN 运行配置，启用并校验内置 DNS，保留有效的订阅解析设置；不回写原始订阅，不改变系统代理或 Manual 的 DNS 意图，也不开放额外的局域网 DNS 监听。

## 分阶段启动验收

Windows 启动区分权限/配置、接口、路由、DNS 与外网检查。有限时间内等待并读取实际网络状态，替代固定等待 900 毫秒后仅凭网站结果判断接管；外网检查后再次核对本地状态。界面和日志显示具体阶段，持续失败与恢复结果分别记录。

外网小型 GET 探测最多 3 轮，共享 30 秒预算；只重试可恢复的失败基础目标。TLS 握手 EOF/连接中断与证书校验、协议错误分别处理，证书错误不放行。已经成功、明确 HTTP 拒绝及首次 OpenAI 专项结果不会因其他目标失败反复请求。不重放模型请求，也不承诺断流可以无缝续接。

Google/Cloudflare 任一基础目标通过仍是外网验收条件；OpenAI 401 仅证明接口响应可达。持续失败仍停止本次 TUN 并按既有流程尝试恢复原模式；取消或会话改变不继续重试旧操作。

## 平台与验收边界

- Windows 仍需管理员会话，TUN 保持实验性；本版没有安装常驻 Windows 服务。
- macOS 兼容包仍不具备 TUN 要求的 Developer ID 与公证；没有绕过辅助服务身份检查。
- Linux TUN 尚未实现，入口继续禁用。
- 验证包含配置回归、模拟接口/路由/DNS 状态、环回网络故障、重试/超时/取消及界面阶段展示；以对应提交 CI 的实际结果为准。
- 未在用户正在使用的主机上执行 TUN 切换、驱动故障注入、关机或重启。真实网络的启停恢复、IPv6/企业 VPN/休眠以及 ChatGPT/Codex 长流需要另行验收，不能用六平台构建通过替代。
