# 逐项诊断

版本：v0.7.37 源码。安装包、下载中心与官网公开状态分别验证，源码版本不等于已经可下载。

## 展示与操作

进入诊断页或点击诊断按钮后，清空上一轮结果并从第一项开始。当前项显示「检测中」和加载图标；该项返回后立即显示真实结果，随后加入下一项。没有等待整个检查完成后再播放列表的动画，也没有用固定延时假装执行进度。

| 顺序 | 检查 | 结果来源 |
| --- | --- | --- |
| 1 | Mihomo sidecar | 当前内置核心探测 |
| 2 | 运行状态 | 当前核心运行态 |
| 3 | 活动配置 | 重新读取当前选用配置 |
| 4 | 系统代理 | 重新读取本应用接管状态；当前模式不要求接管时说明跳过 |
| 5 | Mihomo API | 当前控制接口响应 |
| 6 | 本地代理端口 | 当前 mixed port 的回环 TCP 连接 |
| 7 | 控制接口端口 | 当前 controller port 的回环 TCP 连接 |
| 8 | 实际代理请求 | 经当前本地代理请求固定连通性目标 |

单项未通过保留原因，后续独立检查继续执行。核心未运行时，后四项明确跳过；运行态读取失败时说明无法确定运行状态，不把未执行项算作通过。结束后汇总通过、注意、未通过与跳过数量。

诊断执行期间按钮禁用，重复调用复用同一任务；重新诊断开始新一轮。先前行使用稳定 DOM 标识保留，错误文本进行转义，减少动态效果时停止图标旋转。

## 结果归属与只读边界

每轮绑定当前页面、配置/修订、核心会话、运行操作修订及应用生命周期。离开页面立即标记中断；等待中的请求返回后先核对归属，变化后不采用迟到结果，也不继续后续检查。原生请求尚未结束时不会启动重叠诊断，结束后可重新检查。

新原生命令 `run_connectivity_diagnostic_step` 只接受 `local_proxy`、`controller`、`http_proxy` 三种步骤，每次执行一项。两个 TCP 步骤各有 2 秒时限，并使用异步连接；HTTP 步骤沿用 10 秒请求时限和现有固定目标。设置读取在受限后台读取通道执行，原生生命周期在探测前后复核。旧的批量原生命令保留兼容，当前界面不再使用它。

所有诊断都是只读观察，不启动核心、不接管系统代理/TUN、不变更路由或出口。固定目标响应只代表对应探测结果，不能证明所有网站、登录、模型请求或持续流成功。

## 验证范围

- 逐步延迟响应的回归覆盖：每步完成前只有已完成前缀和当前检测项，后续步骤不提前出现；原始发布快照不会被后续修改。
- 覆盖重复点击、失败后继续、运行态未知/停止、非系统代理模式、步骤标识不匹配、页面/配置变化、生命周期暂停、重试与错误文本转义。
- Rust 使用独立回环监听验证选择的端口和经本地代理发出的 CONNECT，模拟失败不访问外部服务；阶段参数只接受白名单。
- 实际前端在隔离 Tauri IPC 夹具中验证桌面与窄窗口、加载/失败/重试/中断/跳过和减少动态效果，不调用用户应用、真实核心或代理。该范围不替代用户实机网络与模型长流验收。
