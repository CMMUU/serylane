# Serylane v0.7.17

## TUN 启动修复与稳定性

- 修复预检成功返回空值后被前端误判为失败，导致“检查通过”但不继续启动的问题。
- 切换前读取实际状态，预检失败保留旧网络；停止后保存失败、新模式启动失败均尝试恢复原模式，并保留恢复结果与错误详情。
- 核心未进入 running 不显示成功；切换锁保持到最终读回，避免重复点击交叉操作。
- macOS 状态检查共享单次请求，等待中显示「正在确认服务」，不把并发读取当作连接故障；不再因短暂异常自动重新安装辅助服务。
- macOS 心跳清理按本地会话代次和服务端租约核对，旧回调不停止新会话。辅助服务拒绝覆盖运行中的配置；原生校验使用私有、有容量与时间限制的输出文件，避免管道积压。
- Windows 管理员状态与 macOS 服务操作分离；Linux TUN 尚未实现，入口明确禁用并说明。
- 应用日志增加固定阶段与错误码，界面说明预检、启动、恢复各自的状态，不记录配置正文或凭据。

## 升级注意事项

macOS 辅助服务协议升级为 **v2**。旧辅助服务需要在停止代理后，主动点击设置中的「更新辅助服务」，按系统提示核对授权；不会在点击 TUN 时自动修复。Windows TUN 仍为实验性功能，Linux 应用快选不代表已支持 TUN。

详见 [TUN 启用与兼容性](TUN启用与兼容性.md)。

## 验证与发布范围

包含真实前端函数的 IPC `null` 回归、模式切换和失败恢复、平台状态与重复操作测试，以及 Helper 单飞、会话代次、租约和校验边界测试。界面验证使用合成数据，不启动本机真实核心、不修改代理或路由。

真实 TUN 路由、DNS、休眠唤醒、所有平台的安装授权和长期网络稳定性另行验收；XPC 底层同步调用的硬超时仍未全面实现。源码说明不等于安装包已发布。GitHub/Gitee 对应版本附件、签名清单及官网动态下载结果全部核对后，才算完整交付。
