# Tailscale 共存方案二：实施与待验收

[业务契约](当前实现与业务契约.md) · [macOS 交互候选修复](macOS交互优化-待验收说明-2026-11-04.md) · [统一项目文档](https://github.com/CMMUU/project-docs/tree/main/serylane)

2026-11-04 用户确认方案二。基于远程 main `40e2d425` 及已提交的 macOS 交互候选修复继续实施；本说明描述候选源码，不是已发行能力。

## 第一性原理与交付范围

先识别网络路径变化、证明失败阶段，再改变路由。默认共享系统出口：不切换 Tailscale Exit Node，不关闭 MagicDNS，不强行绑定物理接口，不覆盖订阅显式 interface-name/dialer-proxy/routing-mark。

已实现：

- 后台串行、有界地读取系统网络与 Tailscale 状态。macOS 获取网络接口、IPv4/IPv6 默认路由及系统 DNS；Windows 读取接口、默认/Tailscale 路由与 DNS；Linux 读取接口、IPv4/IPv6 路由表、IPv4 策略规则与 resolv.conf。Linux 的 systemd-resolved 分域上游和 IPv6 策略规则尚未完整采集。
- 每轮系统命令共用 3 秒预算，单个命令限时、限输出、超时后终止并回收；生命周期结束/更新时不继续派发。默认间隔 6 秒，采集加间隔不是实时 OS 事件监听。
- CLI 缺失、权限/读取异常显示“未确认”，不推断成关闭；出口离线、未运行和运行中分别展示。原始网络/Tailscale 内容仅用于内存比较，不输出到 IPC 或日志、不持久化。IPC 仅携带随机修订号、递增代次及粗粒度状态。
- 网络拓扑、DNS 或 Exit Node 变化，以及超过 20 秒的采集间隔（包括休眠恢复），更换网络修订号。后台任务与单节点测速采用相应修订；旧批次取消、不重开，不把未测结果记为零延迟，不自动改选节点。
- 自选节点列表不再用未绑定当前网络的核心历史延迟排序；“当前节点”中的核心历史信息明确标为历史。AI 策略已保存的筛选记录仍为历史记录，不自动改写已有出口策略。
- 诊断页可选已加载节点，基础检查之外增加系统 DNS、系统 TCP 对照、Mihomo 实际协议请求。每阶段给出通过、注意、失败或跳过；UDP/未知协议、显式拨号链不伪造 TCP/UDP 握手结论，提供器未确认端点时跳过端点探测、保留核心协议测试。
- 节点分段诊断总预算每项 14 秒；最多两个并发诊断。系统 DNS 线程限两条，超过前台等待预算仍持有槽位至实际结束，避免重复超时累积线程。IPv4/IPv6 TCP 对照最多四并发，域名地址最多采用 16 个。
- 网络变化时已完成诊断也标为历史、要求重测。退出页面/配置变化不采用迟到响应；不修改代理或节点选择。

## 保持关闭的能力

`independentEgressAvailable=false`、`tunCoexistenceVerified=false`。尚未在用户的 Exit Node 故障现场证明独立物理出口、TUN 路由排除与分域 DNS 生效，因此不暴露可误报成功的开关、不生成自动排除规则。这是方案二的分阶段能力门禁，不能将当前候选代码称为“已解决全部共存故障”。

真实长连接、MTU/PMTU、特定 UDP 协议稳定性尚未验收。TCP 对照不是代理 TLS/认证握手，系统 DNS 对照不是 Mihomo 自定义 DNS；核心单次请求通过不代表模型会话稳定。无 Tailscale CLI 时仍可观察部分 OS 网络变化，但识别不完整。

## 验收与发布

- 新增上下文代次、休眠/未知状态、只读命令限时、旧结果失效、迟到回复、协议分类、显式拨号保留和历史排序测试。
- 本机隔离 UI：1320×900、1024×900，12 项逐项诊断、选定节点传参、网络切换中断迟到结果、自选测试旧值失效、无网络变更 IPC、无控制台异常。测试数据均为合成，不作为 Exit Node 真实网络实测。
- Rust 首次受限环境中的临时原生应用启动测试失败；同一隔离测试在获准原生启动的环境重跑通过。具体测试数量以统一项目文档最新记录为准。
- 官网现有功能描述已检查。本轮不把候选能力写成已上线，不部署官网、不改下载中心或发行版本。
- 待完成：用户真实 Exit Node 故障现场、六平台新提交 CI、macOS 内置屏其他应用全屏菜单点击验收。全部门禁完成后再审阅合并、发版、中心归档、官网更新及公开验收。
