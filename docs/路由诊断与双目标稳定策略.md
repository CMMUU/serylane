# 路由诊断与双目标稳定策略

适用源码版本：v0.7.13。实际可下载版本以正式发布页为准。

## 错误与日志

本地路由能返回 502，说明请求已经到达本机监听器，不等于 OpenAI 返回了 502。发送阶段失败时分别显示本地出站代理不可达、DNS、TLS 握手、证书校验、连接超时、连接重置或未能细分的发送失败。只有读到上游响应头，才标记其真实 HTTP 状态。

401、403、429、服务端 5xx 和明确的模型失败/未完成事件单独说明，不直接作为节点质量失败。证书错误不通过关闭证书校验解决。取消请求、原生 WebSocket 隧道关闭不等同于节点故障。

「路由」展示最近异常时间、入口、阶段、耗时、分类、真实上游状态及出口是否核对；这是历史事件，不代表当前仍故障。「日志 → 应用日志」增加“本地路由”来源，同类诊断最多每 30 秒入库一次。沿用默认 3 天、可配置 1–90 天、256 KiB / 2,000 条的容量上限，达到容量上限可能提前淘汰旧记录。只记录固定类别和元数据，不持久化错误原文、完整 URL、路由密钥、认证头、提示词或模型输出。

## 双目标检查

- ChatGPT：`https://chatgpt.com/robots.txt`，预期 200。
- OpenAI API：`https://api.openai.com/v1/models`，未认证预期 401。
- 预期响应检查失败时，补一次不限定 HTTP 状态的基础检查。收到 HTTP 但未验证预期响应，记作“HTTP 可达，预期响应未验证”，不计模型成功或节点失败。控制 API 不可用、认证异常、配置变化、无效结果均是未知，不处罚节点。
- 基础探测不执行模型请求、不使用用户登录凭据，也不做大流量带宽测速。最多 10 个预算内候选，最多并发 2 个节点，每节点串行检查两个入口；每次核心检测 5 秒，本地控制请求最多 7 秒。每轮结束后约 60 秒再检查；故障提示合并，轮次之间至少 30 秒，不重叠。基础检查仍消耗少量流量。
- 默认以 ChatGPT 作为选点依据；显式启用的本地路由使用 API Key 入口时，改以 OpenAI API 为依据。切换目标时清除旧目标的评分证据。两个目标的结果分别展示，超过 240 秒视为过期。API 401 和 ChatGPT 200 都不代表模型流验证成功。

该流程只在稳定策略开启、核心运行且不是手动固定节点时执行。基础 Fallback 与首次生成候选池的筛选流程不在本次替换范围。

## 故障反馈与选点保护

连接失败只触发限频复查，不能凭失败发生时的组选中值推断实际出口。只有默认本地出站、实际 TCP 来源端口和 Mihomo 连接链一致、目标一致且观察期间选择未变化，兼容路由的模型完成/流中断才进入节点评分。

正常节点继续使用。节点独立连续失败后冷却 5 分钟，冷却后需 3 次恢复检查。多个候选同时失败时，先保留当前仍在候选且符合预算的出口复查，显示公共网络/目标服务可能异常，不逐个处罚所有节点。没有合预算候选仍不会偷偷使用高倍率节点。

探测结束后重新核对核心 PID 与启动时间、活动订阅和版本、手动选择、成本策略修订、路由目标和组选中值，过时结果不写入或切换。只影响后续新连接；不删除现有连接、不定时重载核心、不重放模型 POST，也不承诺恢复已经断开的数据流。

## 验证边界

单元/隔离 HTTP 测试覆盖错误私密性、账号错误保留、无请求重放、控制器异常、双目标证据隔离、探测新鲜度、共享故障、冷却、成本与手动优先保护。前端使用合成 IPC 检查状态和独立确认流程。真实登录、长时间模型会话、外部节点波动以及系统登录/重启应另行验收；发布和测试不授权接管用户正在使用的网络或安装替换当前应用。
