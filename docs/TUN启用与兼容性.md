# TUN 启用与兼容性

[文档索引](index.md) · [三端稳定化方案](TUN三端稳定化方案-2026-10-30.md) · [集中分析与验收](https://github.com/CMMUU/project-docs/tree/main/serylane)

## 当前状态（2026-10-30）

本页已按 v0.7.33 代码核对。Windows TUN 仍为管理员会话下的实验功能；macOS 已有权限辅助服务，但兼容发行包不包含 Developer ID 或公证，不满足现有 TUN 身份要求；Linux TUN 仍未实现并保持禁用。三端稳定化的架构、依赖和验收门禁见[方案文档](TUN三端稳定化方案-2026-10-30.md)，不能把待实施方案视为当前功能。

## 先区分三件事

1. **权限与配置检查通过**：具备继续启动的条件，此时尚未切换网络。
2. **启动与接管验收通过**：核心进入运行状态，并完成当前平台的 TUN 检查。
3. **具体应用可用**：登录、模型流、UDP、休眠后重连等需要分别实测，不由预检成功推导。

v0.7.16 存在前端把成功的 Rust `()` / IPC `null` 当作失败的问题，表现为“预检完成”后停住。v0.7.17 按命令是否成功完成判断，不再判断空返回值。

## 平台范围

| 平台 | 运行方式 | 当前兼容处理 |
| --- | --- | --- |
| macOS 13+ | 普通权限应用与特权辅助服务 | 单飞状态检查、待确认状态、会话租约隔离、配置校验有界输出；仍受发行签名与授权条件限制 |
| Windows 10/11 | 整个应用以管理员身份运行，TUN 仍为实验性 | 与 macOS 服务操作分离；权限不足保留原模式并给出下一步 |
| Linux | TUN 网络接管尚未实现 | 禁用 TUN 入口；可使用当前实现的普通系统代理/手动代理能力，不代表已禁用的程序代理可用 |

## macOS 辅助服务升级

当前协议为 **v2**，支持按当前会话租约停止操作。旧服务会显示需要更新，不自动重新安装：

1. 先保存工作、停止代理；确认界面已停止。
2. 打开设置中的 macOS TUN 权限服务，点击「重新关联辅助服务」（v0.7.17 中称为「更新辅助服务」）。
3. 按系统提示核对辅助服务授权，再刷新状态。
4. 显示已就绪后，明确点击 TUN 启动。

「正在确认服务」不是授权失效；稍后刷新即可。连接异常不触发自动修复。更新辅助服务是独立主动操作；下载新版或打开设置不会自动切换当前网络。

### v0.7.18 起：按具体原因处理

历史 v0.7.18 使用临时签名发行流程。项目更新签名用于校验下载完整性，不等于 Developer ID 或 Apple 公证；采用该流程的 macOS 包不满足 TUN 身份要求。实际可下载版本以下载中心为准，并核对对应版本的签名说明；重新下载同一临时签名包不会解决身份缺口。

| 提示 | 含义与下一步 |
| --- | --- |
| 需要更新安装包 | 安装包缺少有效 Developer ID 签名、内容变化或主程序与辅助程序签名团队不一致。安装完整正式版本；反复授权或重新关联不是签名修复方式。 |
| 需要重新关联 | launchd 登记仍在，但辅助程序启动失败。先停止代理，再主动重新关联服务；仍失败时保留诊断信息。 |
| 等待批准 | 在系统设置的登录项与扩展中允许 Serylane；不反复注销和登记。 |
| 正在确认服务 | 签名或握手检查进行中。XPC 等待有界，超时后显示具体错误，不永久把失败显示为初始化。 |

代码会在修复前核对完整安装包，旧服务退出完成后再登记并验证当前 Helper 版本。正式签名发行流程另行要求 Hardened Runtime 和 Apple 公证；Developer ID 检查本身不等于公证或 TUN 网络验收已通过。

### v0.7.19 功能更新（macOS TUN 暂未就绪）

安装检查失败显示「此安装包暂未满足 TUN 要求」，点击「查看诊断」核对原因；不再把旧模式联网成功项展示在 TUN 错误下。默认发行流程要求 Developer ID、同团队签名、Hardened Runtime 与 Apple 公证。v0.7.19 按明确选择先发布项目更新签名的兼容包，不包含 Developer ID 或公证，因此不能作为 macOS TUN 已就绪的依据，辅助服务身份检查保持不变。采用兼容模式的后续发行包也有相同边界。正式签名后，旧版登记仍需停止代理后主动重新关联；真实握手和网络接管单独验收。

## 失败与恢复

- 预检失败：原模式不变，未停止原核心。
- 原核心停止后保存模式失败：仍尝试恢复原模式与原运行状态。
- 新核心返回 crashed / 非运行状态：不显示启动成功；恢复结果与原始错误分别呈现。
- 恢复时观察到其他正在运行或变化中的会话：保留现场、提示刷新，不自动停止它。
- 操作锁持续到最终状态读回；重复点击不重复启动。

macOS 旧心跳返回后须同时通过本地 generation 和 Helper 租约核对，避免旧失败清理新会话。运行中的 Helper 拒绝 prepare/start 覆盖当前配置与进程；用户主动停止仍保留现有明确停止语义。

## 日志和验证边界

应用日志记录固定的权限、配置校验、特权校验阶段和错误码，不记录订阅链接、配置正文、令牌或模型数据。分享技术详情前仍应检查个人信息。

隔离的 IPC/界面和生命周期测试不切换用户正在使用的系统代理。v0.7.17 的 macOS XPC 底层同步调用存在长期等待风险；后续实现已改为有界异步响应，并补充只读 launchd 诊断。Windows 的 Job Object、关机门禁和恢复协调不能代替真实驱动、DNS、路由恢复验收；macOS 实机新安装/升级、休眠与网络切换，以及 Linux 未来 TUN 实现也需独立验收。

当前 TUN 启动后的 HTTPS 检查只能描述目标连通性，不能单独证明流量经过 TUN，也不能证明 ChatGPT/Codex 长流稳定。接管状态与网络健康分离、特权服务统一和网络资源恢复账本均属于[待实施稳定化方案](TUN三端稳定化方案-2026-10-30.md)。
