## 下载与更新

- 官网六架构安装包由下载中心提供。应用内按 GitHub 直连、官网 GitHub 加速代理、经已运行的 Serylane 本地代理访问 GitHub、下载中心的顺序查询正式版。
- 软件更新按顺序自动选择渠道。检查结果显示实际来源及尝试记录，便于排查失败。
- 自动检查开启时，由应用进程在启动后后台检查。发现新版本时，右下角显示卡片，侧栏版本号显示红点。卡片关闭后，红点继续提示，点击版本号进入软件更新的下载操作。无新版和检查失败显示在软件更新面板。
- 版本、平台、架构、签名、大小和 SHA-256 用于核对同一工件。传输失败可尝试下一路径，校验失败提示用户重新检查。下载有界且可取消。安装仍由用户确认，并执行平台预检及回退。
- 旧设置仍可读取。应用内使用自动路径顺序，历史签名工件和标签按发行记录识别。

## 界面语言

- 官网 Windows 安装包在交互式新装时提供语言选择。macOS、Linux、Windows MSI 或其他缺少安装选择的全新配置，在首次打开主窗口时提供一次语言选择。
- 两个入口按原有顺序显示 11 个母语名称和「跟随系统」，预选系统匹配的语种。无匹配时预选英语。安装器完成后把偏好交给应用，应用首次创建配置时保存语言。升级和保留配置重装沿用已有设置。静默或被动更新直接继续。
- 「设置 → 界面语言」随时可切换。保存后即时更新当前窗口和应用原生菜单。
- 官网独立使用同一 11 语种清单；首页、使用指南和主要文档从网址确定语言。官网默认外观跟随系统，不影响桌面端设置。

代码入口：`src-tauri/src/app_update.rs`、`app_update/transport.rs`、`app_update/transaction.rs`、`src/app-update.ts`、`website/src/worker.ts`。

## 当前代理业务

- macOS 菜单栏使用 AppKit `NSMenu`。左键或右键点击仅图标或双行流量状态项，在普通桌面或其他应用的全屏空间打开原生菜单。系统管理外观、勾选、禁用与收起。选中命令后收起，已提交的操作在后台继续。
- 菜单进程启动时，原生状态项先参与系统布局。监测到外框稳定后，用最新流量样本重绘并显示按钮。等待预算为 300 毫秒，达到预算时恢复按钮显示并记录超时。

- Manual 仅提供本地端口；System Proxy 管理操作系统代理；TUN 能力按平台限定。主启动按钮沿用保存的模式，普通关闭操作保留上次模式，不再隐式改成 Manual。
- 关闭当前系统代理或 TUN 与「停止」共用停止流程：记录关闭意图、取消后台恢复、恢复本应用拥有的系统代理设置并停止核心。完成后主状态显示已关闭，关闭失败或状态读取失败显示未完成或待核对，不能仅靠关掉高亮表示成功。
- 主页开关、顶部状态与侧栏依据核心和当前接管状态呈现；保存的网络模式只表示下次启动方式。显式使用 Manual 的旧设置继续保留，本地端口运行不等于系统代理或 TUN 已开启。系统全局流量独立于这些状态，关闭代理后仍可能有网卡流量。
- 自选节点保留原策略组。AI 代理重新筛选后使用两轮轻量探测，检查 ChatGPT 的 robots.txt 是否返回 200 和 OpenAI 的 /v1/models 是否返回 401。至少一个合格候选可启用，只有一个时没有备用；无合格候选则拒绝生成。
- AI 节点评分权重为可归因的真实流完成率 45%、连接可达率 25%、流量倍率 20%、延迟与波动 10%。真实流样本不足时使用其余可用指标给出暂定推荐。普通系统代理不具备可归因的真实流完成信号，界面显示「待验证」。
- 当前节点健康时继续使用。确认故障后，按当前订阅内的合格节点排名为后续连接选点，失败节点进入冷却。AI 候选和有有效推荐结果的订阅显示顺位；实际出口单独标示。手动选点和恢复自动保留，订阅由用户选用。已有基础 Fallback 策略在重新筛选前继续使用。
- AI 代理页「当前 AI 节点」查看 AI 策略组。合格且倍率明确时，点击「应用节点」直接提交；规则允许的未知倍率仍需确认。核心按目标策略组读回实际出口；只有当前配置、当前核心、实际出口和手动固定意图一致时，所选节点的按钮才置灰为「已应用」，不会重复提交。选择其他节点可应用；同一节点在自动模式中也可手动固定。核对不等待全量列表刷新；失败、待核对或仅设为优先不显示已应用，不自动重放写入。只影响命中该组的后续新连接，不主动断开已有连接。
- 健康检查、应用节点和单项／批量测速在触发按钮上展示加载，防止同一操作重复提交；后台刷新保留控件焦点及尚未应用的选择。
- 加权自动选点通常每 8 秒探测当前出口，每 60 秒轮询一批备用候选。明确失败时复核当前出口和备用节点的同一目标。只有得到可区分的失败与通过证据才切换。未知、共同故障及未经确认的健康状态不会触发切换。真实故障恢复时间按现场报告记录。
- 流量倍率由用户核实，未知倍率单独处理。性价比模式的倍率预算作用于实际有效候选。旧增强稳定后台策略仍受能力开关限制。
- 域名路由在 Mihomo 中生成高优先级工具域名规则，选定出口、保存草稿与确认应用独立。路由配置开关保存策略意图，实际状态同时说明规则核对和流量入口；读回规则通过不单独代表系统已经接管。
- 主代理关闭时，已启用路由保留名单和出口并显示「已启用 · 暂停，等待代理启动」；再次启动后加载已应用策略，核对规则和当前系统代理/TUN 入口后显示就绪。显式 Manual 只说明本地代理入口，不能显示系统流量已接管。
- 单独保存、开启或关闭路由不启动核心、不改变主代理启停意图、不切换系统代理/TUN。出口缺失、非规则模式、规则不一致及读取失败分别说明原因；缺失出口仍拒绝匹配流量，不静默改用其他出口。启停、模式/订阅变化使旧路由核验失效，操作完成后重新读取。
- 新增 Codex 接入及程序代理被后端能力开关阻止，历史配置保留；旧接入仅按所有权检查恢复。不会重新启用本地 Responses 中继来掩盖网络问题。
- 401 只说明目标路径到达认证响应阶段；网站检测成功不代表真实模型会话或持续流已验证，切换节点无法无缝续接断流。

代码入口为 `capabilities.rs`、`openai_policy.rs`、`openai_ranking.rs`、`openai_stability.rs`、`effective.rs`、`domain_routing.rs` 与 `routing/`，均位于 `src-tauri/src/`。

## 启动、订阅与日志

- macOS 原生菜单显示当前状态与已缓存的网卡流量，关闭流量显示时保留同源 S 图标。选择「打开主窗口」显示已加载的原页面。WebKit 内容进程中断时，从应用入口恢复界面，连续恢复失败时提供重试。Windows 和 Linux 使用系统托盘。
- 菜单和主窗口使用同一代理控制器：支持系统代理 / TUN、路由开关、刷新状态、按已保存模式启动、停止与读回。代理操作互斥，忙时不重放；TUN 预检先于任何停机，失败只在可安全恢复时回退；网络接管与外网健康探测分开。菜单路由应用已保存的设置，仍需确认；已配置、暂停、待核对和生效分别显示。无已保存出口时进入主窗口设置，不自动应用草稿。
- 新安装默认不随登录启动；后台恢复选项保存后才注册登录项。静默仅控制窗口，恢复使用上次实际意图：之前运行则按原模式尝试恢复，之前停止则保持停止。仅保存路由启用状态不构成主代理开启意图；主代理停止时，登录恢复不会因路由已配置而自动启动它。
- 「添加订阅」在弹窗填写。点弹窗外、按 Esc 或点关闭只收起，草稿仅当前会话保留；已提交的任务继续，可重新打开查看进度或主动取消。失败或取消保留草稿，已确认保存或确认订阅已存在后清空。下载路径仍在订阅页面独立设置。
- 订阅配置下载与套餐用量刷新分别计时、记录状态；失败保留可用旧配置。连接与完整下载有时限，不通过静默切换系统代理处理超时。
- 订阅卡在摘要中对齐展示推荐顺位、实际选用、套餐用量、到期、配置更新时间和异常状态。展开区提供用量采样、详细原因和订阅操作。保留旧记录时按原采样时间展示。
- 应用日志默认保留 3 天，可设 1–90 天；正文最多 256 KiB / 2,000 条，容量达上限可提前淘汰。存储保持紧凑，展示按时间和级别格式化，不存储对话正文或订阅凭据。
- 核心状态查询不再创建版本探测进程；系统结束会话期间暂停新核心任务，取消关机后恢复。具体机器的登录、注销、关机和网络恢复需要独立实测。
- 分层诊断按真实检查进度逐项展示，当前项显示检测中，完成后立即更新结果并继续下一项；单项失败不丢弃此前结果。核心未运行时明确跳过网络项。离开页面、代理/配置变化或会话结束后，不采用迟到结果；诊断不启动核心、不修改系统代理/TUN 或选择出口。详情见[逐项诊断](逐项诊断-实施说明-2026-11-02.md)。

## TUN 与验收

Windows 当前整应用提权且实验性；macOS 通过 `utun` 和特权辅助服务接管，使用带 Developer ID 签名和 Apple 公证的完整安装包；历史临时签名兼容包仍不满足 TUN 要求。Linux 当前没有接管实现。完整方案见 [TUN 三端稳定化方案](TUN三端稳定化方案-2026-10-30.md)。

macOS 在应用内更新或 Finder 覆盖后的首次启动检查安装位置、代码签名与 Helper 状态。确认本应用的旧登记已停止且返回 `EX_CONFIG` 时，应用保留恢复记录并尝试一次原生重关联。确认旧服务从 launchd 移除后才重新登记。新版 Helper 通过身份、版本和协议握手后显示就绪，并清除恢复记录。系统要求批准时，在「登录项与扩展」批准 Serylane 后返回应用继续。应用日志记录许可、注销、移除确认、重新登记、握手及系统错误。首次安装辅助服务由用户发起，网络接管按保存的启停意图执行。

macOS 获得辅助服务批准并准备好 TUN 接口后，系统代理与 TUN 共享普通用户 Mihomo 进程及配置的本地端口。辅助服务核对会话与进程身份，切换 IPv4、IPv6 路由并批量应用系统代理。系统代理生效或 TUN 基础连通性通过后更新主窗口和菜单状态。切换失败时尝试恢复原模式的配置、路由和代理设置。兼容启动遇到自有端口的旧连接收尾时，最多等待 35 秒，遇到真实监听则报告冲突。

v0.7.35 在有效 TUN 配置中启用并校验内置 DNS，保留原始订阅。Windows 启动增加接口、路由与 DNS 的有界就绪检查；完成后独立检查外网，再次读回本地状态。外网最多 3 轮、共享 30 秒预算，仅重试可恢复的失败探测；TLS 握手中断与证书/协议错误区分处理，不降低 TLS 校验。持续失败仍回退，并区分失败阶段与恢复结果。

v0.7.45 的已公证候选在本机 Apple 芯片的 macOS 27.2.1 隔离虚拟机实测：复现旧 Helper 启动失败、确认新版重关联、接管未显式配置 HTTP 代理的 TCP 和外部 IPv4 HTTPS、停止后恢复路由与系统代理。该结果不等同于 Intel 实机、休眠唤醒、IPv6、长期连接或全部订阅组合的验收。实际下载包以对应发行记录为准。见 [v0.7.45 发布说明](发布说明-v0.7.45.md)。

十项优秀线、竞品对照和最小测量仪见[代理质量验收](代理质量验收.md)。发布检查使用隔离样例验证计算及证据边界。完整现场成绩由实际采样给出。

## 文档同步规则

1. 变更业务先核对真实后端、生命周期与发行配置，再修改用户说明。
2. 自动事实表从版本、能力开关与节点约束生成；提交时检查不一致即失败。该检查不替代对手写说明与运行行为的审查。
3. 当前索引、README、官网和集中项目文档同步；历史发布说明标为历史记录，不覆盖原验收证据。
4. 记录代码提交、测试结果、发布版本、中心归档、官网验证与尚未执行的实机测试。源码通过不等于生产已交付。
