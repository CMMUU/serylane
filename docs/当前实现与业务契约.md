## 下载与更新

- 唯一产品下载来源为 [下载中心](https://downloads.cmmuu.com/projects/serylane)。应用读取中心版本 API，官网六个系统/架构入口也只解析该中心。
- 旧设置中的自动、GitHub、Gitee 偏好迁移为下载中心；其他用户设置保留。旧线协议标识 hk 属于兼容数据，不是额外渠道。
- 元数据必须匹配版本、平台、架构、大小、摘要与签名；真实文件必须位于中心专属文件路径，不能通过下载重定向切换来源。中心不可用、未同步或文件不完整时提示失败和重试。
- 网络波动使用有界重试，下载可取消，完整性失败不安装。安装确认、原生预检、停止旧进程、替换与失败恢复仍独立执行；不因检查或下载变更当前代理。
- 源码仓库与发行归档是维护设施，不是用户下载备用渠道；历史已签名产物、标签和审计记录保持不变。

代码入口：`src-tauri/src/app_update.rs`、`app_update/transport.rs`、`app_update/transaction.rs`、`src/app-update.ts`、`website/src/worker.ts`。

## 当前代理业务

- Manual 仅提供本地端口；System Proxy 管理操作系统代理；TUN 能力按平台限定。主启动按钮沿用保存的模式，普通关闭操作保留上次模式，不再隐式改成 Manual。
- 关闭当前系统代理或 TUN 与「停止」共用停止流程：记录关闭意图、取消后台恢复、恢复本应用拥有的系统代理设置并停止核心。完成后主状态显示已关闭，关闭失败或状态读取失败显示未完成或待核对，不能仅靠关掉高亮表示成功。
- 主页开关、顶部状态与侧栏依据核心和当前接管状态呈现；保存的网络模式只表示下次启动方式。显式使用 Manual 的旧设置继续保留，本地端口运行不等于系统代理或 TUN 已开启。系统全局流量独立于这些状态，关闭代理后仍可能有网卡流量。
- 自选节点保留原策略组。AI 代理重新筛选后使用两轮轻量探测，检查 ChatGPT 的 robots.txt 是否返回 200 和 OpenAI 的 /v1/models 是否返回 401。至少一个合格候选可启用，只有一个时没有备用；无合格候选则拒绝生成。
- AI 节点评分权重为可归因的真实流完成率 45%、连接可达率 25%、流量倍率 20%、延迟与波动 10%。真实流样本不足时使用其余可用指标给出暂定推荐。普通系统代理不具备可归因的真实流完成信号，界面显示「待验证」。
- 当前节点健康时继续使用。确认故障后，按当前订阅内的合格节点排名为后续连接选点，失败节点进入冷却。AI 候选和有有效推荐结果的订阅显示顺位；实际出口单独标示。手动选点和恢复自动保留，订阅由用户选用。已有基础 Fallback 策略在重新筛选前继续使用。
- 流量倍率由用户核实，未知倍率单独处理。性价比模式的倍率预算作用于实际有效候选。旧增强稳定后台策略仍受能力开关限制。
- 域名路由在 Mihomo 中生成高优先级工具域名规则，选定出口、保存草稿与确认应用独立。路由配置开关保存策略意图，实际状态同时说明规则核对和流量入口；读回规则通过不单独代表系统已经接管。
- 主代理关闭时，已启用路由保留名单和出口并显示「已启用 · 暂停，等待代理启动」；再次启动后加载已应用策略，核对规则和当前系统代理/TUN 入口后显示就绪。显式 Manual 只说明本地代理入口，不能显示系统流量已接管。
- 单独保存、开启或关闭路由不启动核心、不改变主代理启停意图、不切换系统代理/TUN。出口缺失、非规则模式、规则不一致及读取失败分别说明原因；缺失出口仍拒绝匹配流量，不静默改用其他出口。启停、模式/订阅变化使旧路由核验失效，操作完成后重新读取。
- 新增 Codex 接入及程序代理被后端能力开关阻止，历史配置保留；旧接入仅按所有权检查恢复。不会重新启用本地 Responses 中继来掩盖网络问题。
- 401 只说明目标路径到达认证响应阶段；网站检测成功不代表真实模型会话或持续流已验证，切换节点无法无缝续接断流。

代码入口为 `capabilities.rs`、`openai_policy.rs`、`openai_ranking.rs`、`openai_stability.rs`、`effective.rs`、`domain_routing.rs` 与 `routing/`，均位于 `src-tauri/src/`。

## 启动、订阅与日志

- 新安装默认不随登录启动；后台恢复选项保存后才注册登录项。静默仅控制窗口，恢复使用上次实际意图：之前运行则按原模式尝试恢复，之前停止则保持停止。仅保存路由启用状态不构成主代理开启意图；主代理停止时，登录恢复不会因路由已配置而自动启动它。
- 订阅配置下载与套餐用量刷新分别计时、记录状态；失败保留可用旧配置。连接与完整下载有时限，不通过静默切换系统代理处理超时。
- 应用日志默认保留 3 天，可设 1–90 天；正文最多 256 KiB / 2,000 条，容量达上限可提前淘汰。存储保持紧凑，展示按时间和级别格式化，不存储对话正文或订阅凭据。
- 核心状态查询不再创建版本探测进程；系统结束会话期间暂停新核心任务，取消关机后恢复。具体机器的登录、注销、关机和网络恢复需要独立实测。
- 分层诊断按真实检查进度逐项展示，当前项显示检测中，完成后立即更新结果并继续下一项；单项失败不丢弃此前结果。核心未运行时明确跳过网络项。离开页面、代理/配置变化或会话结束后，不采用迟到结果；诊断不启动核心、不修改系统代理/TUN 或选择出口。详情见[逐项诊断](逐项诊断-实施说明-2026-11-02.md)。

## 交互读取（本轮候选源码，尚未发行）

节点详情先显示加载态，读取期间可关闭；迟到响应不重新打开。关闭按钮保持身份和位置。前台状态读取优先，后台最多占 2 个读取槽，总并发上限 4；同资源合并，写操作不合并或自动重试。核心/订阅状态按组提交，补充信息不阻塞整页。主题与设置持久化在后台执行，保留配置变更与生命周期检查。

macOS 候选由独立 AppKit 状态项和菜单持有入口，不再隐藏跨平台依赖的内部事件视图；菜单开合与主窗口恢复分离，动作延后到菜单结束跟踪，状态项回收会撤销点击观察并清除回调目标。流量绘制与显示开关共用主线程的单份最新队列；正常/位图降级与关闭流量后的静态图标使用同源 S。窗口恢复有界核对活动 Space 和焦点，关闭后不会重开，不改变 Dock 形态或用户系统偏好。详情见[待验收说明](macOS交互优化-待验收说明-2026-11-04.md)。真实全屏菜单栏点击尚未验收，不表示已修复用户机器；正式发布、中心归档与官网部署均未执行。Windows/Linux 原有托盘点击方式保留；恢复窗口保留当前页面。

## TUN 与验收

Windows 当前整应用提权且实验性；macOS 有 Helper，但兼容包不具备正式 TUN 签名身份；Linux 当前没有接管实现。完整方案见 [TUN 三端稳定化方案](TUN三端稳定化方案-2026-10-30.md)。

v0.7.35 在有效 TUN 配置中启用并校验内置 DNS，保留原始订阅。Windows 启动增加接口、路由与 DNS 的有界就绪检查；完成后独立检查外网，再次读回本地状态。外网最多 3 轮、共享 30 秒预算，仅重试可恢复的失败探测；TLS 握手中断与证书/协议错误区分处理，不降低 TLS 校验。持续失败仍回退，并区分失败阶段与恢复结果。

本版没有安装新的常驻特权服务、解决 macOS 签名身份或开放 Linux TUN。真实主机 TUN 切换、路由/DNS 恢复、休眠和长流尚需独立验收。实现、签名发布、原生集成测试和真实网络验收必须分别记录。
