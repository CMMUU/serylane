# Serylane — 开源 Mihomo 桌面代理客户端

Serylane 是基于 **Mihomo** 内核、使用 Rust + Tauri 2 构建的开源桌面代理客户端，面向 Windows、macOS 和 Linux。通过中文界面管理 Clash Meta / Mihomo YAML 订阅、节点、分流规则和系统代理，并提供默认关闭的 AI 工具域名路由。

路由启用引导、核心规则回读与失败恢复见 [v0.7.29 发布说明](docs/发布说明-v0.7.29.md)；实际可下载版本以正式发行和下载中心核验结果为准。

**Serylane is an open-source Mihomo desktop proxy client for Windows, macOS, and Linux.** Built with Rust and Tauri 2, it provides subscription management, proxy selection, traffic rules, system proxy controls, and optional local routing for Codex. The local router is off by default; Windows TUN support is experimental.

这是独立客户端项目，并非 Mihomo、Clash 或 OpenAI 的官方产品。Serylane 不提供代理节点或订阅服务，需要使用你自己的订阅与配置。

## 主要功能

- **v0.7.31 单节点与检查反馈**：至少 1 个合格节点即可使用，最多保留 10 个；单节点暂无备用，2 个及以上可自动故障切换。AI 健康检查显示进度、支持取消并保留逐节点结果；订阅配置更新与用量查询分别记录，超时显示下载路径并保留原配置。[发布说明](docs/发布说明-v0.7.31.md)。实际安装包以正式发行记录为准。

- **v0.7.22 下载来源文案统一**：桌面更新渠道、检查结果与提示统一使用“下载中心”，与官网和下载中心一致；保留原有更新偏好、地址、备用顺序和校验规则。[发布说明](docs/发布说明-v0.7.22.md)。
- **v0.7.21 macOS 菜单栏紧凑布局**：双行网速占位从 78pt 收紧到 64pt，保留原字号和同源 S 图形；正常与备用渲染宽度一致，数字变化不挤动相邻图标。仅优化显示，不改代理或 TUN。[发布说明](docs/发布说明-v0.7.21.md)。

- **v0.7.20 订阅稳定性**：完整下载重试、明确下载路径、分阶段进度与取消、配置提交协调；不改系统代理，不涉及 TUN 或 Codex 路由接入。安装包以正式发行记录为准。[本轮发布说明](docs/发布说明-v0.7.20.md)。

- **TUN 启动与失败恢复**：v0.7.17 修复预检成功值误判；v0.7.18 进一步处理 macOS 服务重新关联、有界握手、安装包签名与启动失败分类。按原有 GitHub 流程生成的临时签名 macOS 包仍不满足 TUN 的 Developer ID 身份要求，发布不代表 TUN 已恢复。Windows 保留管理员要求，Linux 暂不提供 TUN。[平台支持与操作说明](docs/TUN启用与兼容性.md)。

- **v0.7.23 节点体验**：自选节点支持可取消的一键延迟/连通性测试；AI 代理最低两个合格节点（一主一备），显示筛选数量；订阅卡片高亮实际选用项。选点方式互斥、Codex 接入独立，TUN 支持范围不变。[发布说明](docs/发布说明-v0.7.23.md)。安装包以下载中心实际发行结果为准。
- **v0.7.19 功能更新**：订阅卡片精简、导入失败处理、配置同步与独立「自选节点」模式；自选节点保留订阅策略组与分流规则，与 AI 代理二选一，Codex 路由接入独立；支持删除当前和最后一个订阅，本地 YAML 单独保留。本轮 macOS 采用项目更新签名的兼容包，尚无 Developer ID 签名与 Apple 公证，**macOS TUN 仍未就绪**。最新可下载版本以下载中心实际发行结果为准。[发布说明](docs/发布说明-v0.7.19.md)。

- **跨平台应用快选与绑定（v0.7.16）**：Windows MSIX / Store、macOS `.app`、Linux `.desktop` 按应用身份关联；正常更新后重新定位入口。macOS 使用原生启动，Linux 普通桌面入口按独立参数启动；特殊激活／沙箱入口明确标为待适配。缓存即时显示，后台刷新不打断编辑，保留普通文件选择和原参数。[使用与验证说明](docs/应用绑定与自动跟随更新.md)。

- **系统代理启动提速（v0.7.11）**：本地接管完成后即可使用，外网检查后台执行；Manual / System Proxy 热切换不主动重启核心。状态提示区分代理已开启、联网检查中和部分检测失败，并提供技术详情。

- **订阅管理**：在「订阅」统一添加远程订阅，明确选择添加后是否选用；本地 YAML 仍在「配置」导入与回滚。用紧凑卡片查看服务商返回的套餐流量、到期时间与更新状态；没有提供的数据会明确标注，不显示成零或不限量。
- **节点与规则**：切换代理组和节点，查看延迟与连接，编辑分流规则，并保留配置版本与回滚入口。
- **系统代理**：管理系统代理；程序代理暂时停用并隐藏，既有条目保留。
- **启动模式与状态保持（v0.7.8）**：登录后后台恢复或显示窗口恢复；上次开启则沿用原配置和模式，上次停止则保持停止。可核对系统登录项，临时网络故障等待重试，停止会取消恢复。macOS 流量托盘与应用共用 S 标记。
- **更清晰的 macOS 双行网速（v0.7.9）**：保留共享 S 图标，使用原生等宽数字、固定数值/单位列和系统亮暗着色；紧凑显示上下行，悬停查看完整速率单位，关闭后回到纯图标。
- **可选 AI 域名路由**：顶部与页内入口同步；缺少配置时引导选择出口并保存，独立确认开启。真实核心规则核对通过后显示生效，异常可重新应用；保留失败回退，不新增 Codex 接入。
- **AI 基础故障切换**：保留最低双节点与基础 Fallback；增强稳定灾备暂时停用并隐藏，性价比预算继续约束实际候选。
- **日常桌面体验**：磨砂玻璃界面、浅色／深色／深紫与跟随系统主题、托盘、流量监控，以及 下载中心优先、Gitee / GitHub 备用的签名更新。

## 快速开始

1. 从上面的 Release 页面选择与系统和处理器架构匹配的安装包；渠道未提供对应附件时使用另一渠道，以实际发布内容为准。
2. 在「订阅」→「添加订阅」输入自己的 Clash Meta / Mihomo YAML 订阅地址，需要立即选用时勾选「添加后选用」；已有选用配置时默认不勾选，未勾选只保存。概览引导会前往同一入口，本地 YAML 仍在「配置」导入与回滚；本项目不提供代理节点或订阅服务。
3. 选用配置，点击顶部主「启动」会按当前保存的网络模式启动 Mihomo 核心；0.7.7 起不会强制改成系统代理。需要切换模式时使用明确的「系统代理」或「TUN 模式」入口，TUN 仍按原流程处理权限和预检。域名路由不会自动修改系统代理／TUN。启用系统代理或 TUN 前先关闭其他客户端的系统代理／TUN，避免相互接管。
4. AI 工具域名路由默认关闭；勾选工具或添加域名、明确选择出口并保存草稿，再确认开启。设置不足时按钮引导到对应操作，不自动选出口；核对核心规则后显示生效。已开启但核对异常时可刷新或重新应用。

## 自选策略组与主页节点详情（v0.7.19）

v0.7.19 将普通策略组选点独立为「自选节点」，与「AI 代理」二选一；以下说明按当前菜单更新。安装包以正式 Release 和官网下载结果为准。

- 确认使用「AI 代理」后可在基础 Fallback 组手动优先选择节点，失效时核心仍可能回退；增强稳定优先暂时停用。
- 不使用 OpenAI 灾备时，切换为「自选节点」，在订阅原有策略组中选择节点，不需要生成灾备、启用本地路由或接入 Codex。Selector 为手动选择；Fallback / URLTest 为手动优先，核心检测其不可用时仍可能回退，界面会显示实际出口；负载均衡等不支持单节点选择的组不会显示误导性切换按钮。
- 「概览」分别展示普通代理和 OpenAI 专用策略组的当前节点、链路、协议、最近有效延迟、脱敏服务器与来源。普通策略组下拉框只改变展示，不改变代理配置。全局模式查看 GLOBAL；直连、核心停止或读取失败时不显示旧节点为当前出口。
- 规则模式没有唯一的全局节点；OpenAI 分流也可能被优先级更高的用户规则覆盖。最近探测可达不代表模型流已验证。选点不重启核心、不主动清空已有连接，只影响命中相应策略组的后续新连接。

## OpenAI 性价比策略（v0.7.10）

「AI 代理」→「成本与性价比」可按订阅逐节点填写流量倍率，支持质量优先（保持旧行为）与性价比优先。倍率由用户按服务商信息填写，空白不是 1×；节点配置身份变化后须重新确认，不能从节点名称或套餐总用量推导费用。

性价比筛选先要求两次基础可达、质量分不低于最佳节点 15 分且不低于 50，再按质量分除以倍率平方根排序，保留灾备的节点多样性。跳过每节点 2 MiB 带宽测试，但基础探测仍使用少量流量；基础可达不等于模型流已验证。稳定故障切换只比较健康且质量相近的候选，保持符合预算的健康当前节点，不为微小价差反复切换。

倍率上限和未知倍率兜底仅在性价比模式生效；未知费用默认不参与。预算过滤编译进基础 Fallback，有效候选少于两个时拒绝托管路径新请求，不擅自扩大预算。保存后校验并重载当前配置，失败恢复原配置；不启动核心、不重放请求，也不自动扩大候选池。实际资费与账单以服务商为准。

## 当前范围

- Clash Meta / Mihomo YAML 订阅和本地文件
- 原始配置与本机控制字段合并
- Mihomo 原生配置校验
- UUID 配置档案、不可变版本、激活和回滚
- 固定版本 Mihomo sidecar 下载、SHA-256 校验和跨平台打包
- Mihomo 生命周期、状态机、端口预检和脱敏日志
- Manual、System Proxy 和 TUN 网络模式
- 代理组、节点切换、延迟、规则、连接和关闭连接
- 独立订阅管理：紧凑卡片、服务商套餐用量与到期时间、检查与采样时间、刷新失败保留旧用量、选用、版本、删除、脱敏来源和导入；未提供数据不显示成零或不限量
- 当前节点详情：实际代理链、Provider、脱敏服务器、协议与健康历史
- OpenAI 基础灾备：最多 10 个候选，至少 1 个；单节点无备用出口；增强稳定策略暂时停用，预算限制继续生效
- 可选 AI 工具域名路由：默认关闭，预置工具与自定义地址统一处理，明确出口和应用确认
- 分层连通性诊断
- System Proxy 本地接管与读回验证、活动物理网卡筛选和失败恢复；外网检查在后台完成
- Windows 系统代理事务恢复、外部客户端接管识别，以及 PAC／代理例外保留
- Windows 10/11 实验性 TUN 管理员会话，核心进程树随停止或退出回收
- 独立于 Mihomo 的 OS 全局实时流量监控，应用内和 macOS 菜单栏均显示纵向上下行速率
- 系统托盘、单实例和登录启动设置

- 高级规则文本导入与可复制导出、独立持久化、最近 20 个历史版本与校验后回滚

## 自定义规则

1. 打开「规则 → 我的规则」，添加匹配条件，选择 `DIRECT`、`REJECT` 或当前配置中的策略。
2. 使用上移／下移调整优先级；未启用的规则保留在编辑器中，但不加入内核配置。
3. 点击「校验草稿」，通过后「保存并应用」。运行中的内核热更新，不先停止代理进程。
4. 「高级文本」接受逐行规则、YAML 列表或仅含 `rules:` 的 YAML；「导出文本」提供只读文本与复制入口，由用户自行保存文件。
5. 在「历史版本与回滚」选择版本并确认。回滚也会校验并生成新版本。

已启用的域名路由优先，其后全局用户规则优先于托管 AI 与订阅规则，更新订阅不会覆盖它们。`DIRECT` 表示进入 Mihomo 的连接从本机直连出口，并非修改系统代理例外列表；不使用系统代理的程序原有直连行为保持不变。规则分流应使用 `Rule` 路由模式。

导出中的 `mihomo-codex-rule` 注释用于本应用恢复启停、备注与顺序。导出内容是规则编辑数据，不是完整代理配置；交给其他客户端前需按其规则格式处理停用条目。

## AI 工具域名路由

- v0.7.27 起，顶部「系统代理／TUN 模式」旁增加独立「路由」开关；页面保留「开启／关闭路由」和「刷新状态」。两处共享确认、执行锁与真实状态。路由是域名分流叠加，不是第三种网络接管模式。
- 编辑后先保存草稿；关闭状态通过任一开关确认启用，已开启时通过「应用更改」更新名单。未保存编辑不被静默应用；关闭路由会保留草稿。核心未运行、非规则模式或出口缺失仍显示具体原因。

- 常见工具：OpenAI / ChatGPT、Claude、Gemini / AI Studio；默认草稿只选 OpenAI。工具清单由后台展开，自定义域名单独编辑，底层统一校验、去重和编译。
- 自定义支持根域及 `*.example.com`；通配符不包含根域。`https://*.example.com/*` 可规范化为域名，具体 HTTPS 路径不静默扩大为整域规则。
- 保存草稿不改变流量，明确选择出口并确认应用后才启用。只处理进入核心的流量，优先于本地、AI 与订阅规则；其他流量保持原规则。缺失目标组时匹配流量拒绝连接，不自动直连。
- 不新增 Codex 接入、不监听旧模型中转。已有接入只按所有权恢复，外部编辑冲突保留备份和恢复入口。旧设置保留，新域名路由默认关闭。
- 程序代理与增强稳定灾备暂时停用并隐藏。基础 Fallback 保留，性价比预算编译进有效候选；不足两个合格节点拒绝托管路径新请求。
- 工具清单的已应用快照不会因升级自动扩大，重新保存并确认应用才更新。共享第三方域名按需自定义。
- [详细域名范围与操作说明](https://serylane.cmmuu.com/docs/routing)。模型请求不自动重放，真实会话与 TUN 支持范围以各版本验收为准。

## Windows 使用说明

- Windows TUN 使用管理员会话：先从托盘退出应用，再右键选择「以管理员身份运行」。整个应用会获得管理员权限，不安装常驻 Windows 服务，也不使用 macOS Helper 的安装/授权流程。普通系统代理不要求管理员会话。
- Windows 内核、配置校验和版本探测进程在创建时绑定 Job；停止、退出或应用进程异常终止会关闭受保护的进程树。关闭主窗口仅隐藏到托盘。系统代理在正常停止/退出时按快照恢复，异常终止后在下次启动尝试恢复。
- 系统代理恢复会核对当前代理是否仍由本应用控制，避免覆盖后来切回的 Clash 等客户端；临时接管会保留代理例外、停用 PAC，并在仍持有控制权时还原原有 PAC。切换前应关闭其他客户端的系统代理/TUN。
- 启动预检以 Google/Cloudflare 至少一个返回预期状态为基础联网条件；OpenAI 仍独立检查并显示警告，专项失败不会阻止基础代理启动。两个基础目标都失败时仍会阻止启动。

**Windows TUN 为实验性功能。** 已实现管理员权限检测和会话内核生命周期；真实 TUN 路由、DNS、停止后的网络恢复及异常退出恢复尚未完成整体验收。单元测试、界面模拟检查和构建成功不代表已通过网络接管验收。

## 发布架构

Tauri sidecar 为各目标平台提供匹配的 Mihomo 二进制：

```text
src-tauri/binaries/mihomo-<target-triple>
```

构建脚本校验固定压缩资产的 SHA-256，并验证当前平台的 `mihomo -v` 输出。CI 在 macOS、Windows 和 Linux 原生 runner 执行。

推送稳定版本标签 `vX.Y.Z` 后，`Release bundles` 在六个平台全部构建成功后自动创建 GitHub Release。标签必须与 `package.json`、Tauri 和 Cargo 版本一致，并提交对应的 `docs/发布说明-vX.Y.Z.md`。发布作业从该标签的锁文件重新生成依赖 SBOM 与许可证清单，核对输入 SHA-256 和项目许可元数据；收齐安装包、签名更新包与兼容别名、Mihomo GPL 许可证及上游源码、项目许可证、`sbom.cdx.json`、`license-inventory.md` 和 `SHA256SUMS.txt`，校验全部通过后才公开草稿。0.7.7 起公开安装包和项目许可证使用 Serylane 名称。重复运行复用内容相同的附件，遇到同名不同内容则停止，不覆盖历史发布包。手动 `workflow_dispatch` 指定正式标签时同样经过完整构建与发布校验。

正常发版也可在 `main` 手动运行 **Release bundles**：选择 `publish_current: true`，留空 `release_tag`。六平台测试、构建和 Windows 隔离安装验收通过后才创建对应的不可变版本标签并发布；默认手动运行只构建、不公开发布。已有正式标签需要修复时使用 `release_tag`，不会移动标签。

源码与发布工作流使用 `CMMUU/serylane`。国内同步明确映射至现有 Gitee 路径，以保持已安装客户端的更新入口有效；应用数据标识、签名密钥和旧更新文件别名属于兼容协议，不随展示名称变更。
