Serylane / Getting started

Set up your connection. Know its limits.

Serylane is an independent desktop client for subscriptions and proxy configurations you already have. It does not provide proxy nodes or sell subscriptions.

This is English website documentation, not a claim that the desktop app has an English interface. Where helpful, current Chinese app labels appear alongside an English explanation. Download availability is determined by verified public download-center records, not by the source version.

Quick start

  1. Open the download section and choose your operating system and processor architecture. Installers come only from the download center. If the matching current package cannot be verified, retry later; do not substitute another architecture or an older release.
  2. Check that release’s notes for supported features and platform requirements. A feature in source code is not proof that it is included in the current downloadable installer.
  3. Add your own Clash Meta / Mihomo YAML subscription through 「订阅 → ＋ 添加订阅」 (subscriptions → add subscription). Import a local YAML file on 「配置」 (configuration). A subscription URL often contains credentials: do not publish it.
  4. If a configuration is already active, adding a subscription does not select it by default. Only the explicit 「添加后选用」 option selects it after adding. Adding or selecting a configuration does not start the proxy; use 「启动」 when you are ready.
  5. Before enabling system proxy or TUN, turn off the equivalent takeover mode in other proxy clients. AI domain routing is optional and off by default; leave it off if you do not need it.

What the current design supports

  • System proxy: serves applications that follow the operating system’s proxy settings. It does not guarantee coverage of every program or connection protocol.
  • Local-port / Manual mode: applications can explicitly use the local proxy port. A running local port does not prove that system traffic has been captured.
  • Domain routing: maps supported AI-tool domains and custom domains to an exit policy group in the current subscription. It applies only to connections already entering the core, in rule mode. The default is off; saving a draft and confirming application are separate. Stopping the main proxy pauses enabled routes without deleting them. It does not decrypt TLS or add Codex attachment. Read the routing guide.
  • AI proxy: accepts 1–10 qualified nodes. Re-screening provides a recommendation order; a healthy current node remains in use. Cost-mode multiplier budgets apply, and one node has no backup. Existing results retain basic Fallback until re-screened. Understand recommendations and failover.
  • Disabled capabilities: program proxy is hidden and off; existing records are retained without scanning or launching external apps. The old enhanced-stability strategy and new Codex attachment are also disabled. Historical app-binding instructions are not current setup steps.

Changing the selected node affects subsequent connections. Serylane does not replay model requests or promise seamless recovery of a disconnected stream. Reachability checks, including an HTTP 401 from an API, do not establish account access or a verified model session.

Subscriptions, node tests and diagnostics

In v0.7.40, adding a subscription opens a dialog. Click outside or press Escape to hide it; reopening restores your draft for this session. An import that has already started continues; reopen the dialog to view progress or cancel.

Subscription cards separate the active selection, configuration refresh and allowance sampling. An added but unselected subscription is not highlighted as active; a local YAML configuration does not highlight a remote subscription. Editing a subscription does not select it, and a changed URL requires a manual refresh.

Manual subscription downloads can follow Serylane, use direct access, or use an already-running local HTTP proxy. They do not start the core or change system proxy settings. Failure on the selected proxy path does not silently switch to direct. Fetching and validation have bounded retries and timeouts; failures retain the existing configuration. Cancellation is available before saving begins, while a started save transaction is allowed to finish.

In v0.7.40, health checks, node selection and speed tests show loading on the clicked button. When the selected AI node is eligible and its cost is known, 「应用节点」 (apply node) submits without a second confirmation. The app verifies the current exit with Mihomo before reporting success. Only new connections matching that policy group use the new exit; existing connections stay open.

Node tests report basic reachability, timeouts and failures, not bandwidth, AI login or successful model requests. They do not automatically start the core or proactively choose an exit; automatic groups retain their own policy. Diagnostics reveal checks progressively, skip network checks when the core is stopped, and do not change proxy modes, routes or configuration.

Read allowance data carefully

Upload, download, plan allowance and expiry values come from the provider’s subscription response. They are sampled provider data, not a real-time bill measured by Serylane.

Missing fields are identified. After a failed refresh, the last successful sample may remain visible: check its timestamp and error. Missing information does not mean zero usage, an unlimited plan or an account that never expires.

One download and update channel

Website installers and the current source update flow use only the download center. Each download click rechecks the current formal release, operating system, architecture and package availability. If the center is unavailable, the matching asset is missing, or verification fails, the result is an error with retry—not another source, architecture or an older version.

Update signature, file size and SHA-256 checks remain required. An older installed client still uses its own updater until replaced; source changes do not change that binary. If needed, obtain a verified full installer for the same architecture from the website and retain the configuration directory. Read verification and update recovery guidance.

Choose the matching system and architecture

  • Windows: x64 · ARM64
  • macOS: Intel (x64) · Apple silicon (M series, ARM64)
  • Linux: x64 · ARM64

These six routes do not guarantee that every current-release package exists. If the matching asset is unavailable or cannot be verified, retry later rather than substituting an older release or another architecture.

Check which chip your Mac uses

Open Apple menu → About This Mac. Choose Intel (x64) for an Intel processor and Apple silicon (M series, ARM64) for an Apple M-series chip. Do not guess from the macOS version or model year.

TUN support is platform-specific

TUN is not a completed, stable three-platform network-takeover feature. Source helper code or isolated automation is not evidence of real-network, DNS, sleep/wake or long-stream acceptance.

  • Windows: experimental, requiring an administrator session. Real routes, DNS, shutdown and recovery need separate acceptance.
  • macOS: helper implementation exists, but the compatibility packages do not include the required Developer ID identity and Apple notarization. TUN is not ready in those packages. Repeated authorization or downloading the same compatibility package does not supply the missing identity.
  • Linux: TUN network takeover is not implemented; its controls are unavailable. Local proxy, system proxy, program proxy and TUN are separate capabilities.

Check the actual package’s release notes. Read the macOS signing and helper boundary. The v0.7.17 workflow and v0.7.35 staged checks below are historical records, not approval of everyday TUN use.

Windows TUN: experimental, with administrator access

Before experimenting, save your work and read the applicable release notes. Exit the client from its tray menu, then deliberately launch it with Windows’ “Run as administrator”. Ordinary system-proxy use does not require an administrator session.

The client attempts to restore network settings on stop or exit according to its state. Closing the main window normally hides it to the tray; it is not an exit. System-proxy restoration checks ownership so it does not overwrite settings subsequently controlled by another client. Do not enable system proxy or TUN in multiple clients at once.

If recovery fails, do not repeatedly switch between takeover tools. Record the error and state, stop the relevant takeover, and inspect operating-system proxy and DNS settings. If the state is unclear, keep logs and use the project issue tracker after removing subscription URLs, tokens and personal information.
