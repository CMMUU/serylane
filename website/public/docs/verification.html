Serylane / 文档 / 校验与签名

下载的文件，有据可查。

安装前核对发布渠道、版本、操作系统和处理器架构。SHA-256 检查文件一致性，更新签名检查更新包是否由项目持有的签名密钥签发；两者不是同一件事。

从项目发布页开始

默认从下载中心 Serylane 项目页获取安装包及校验文件，原始文件名、签名与哈希保持不变。备用渠道为 Gitee Releases 与 GitHub Releases。同版本优先下载中心；若缺少对应版本、架构、格式或校验附件，请使用 GitHub。以实际附件为准，不把源码标签当成已经发布的安装包。

不要仅凭文件名相似判断来源可信，也不要把其他站点重新打包的文件视为项目发布。

核对 SHA-256

  1. 从同一版本的发布页下载安装包和项目提供的 SHA256SUMS.txt。
  2. 计算安装包的 SHA-256，在校验文件中找到完全相同的文件名，逐字核对摘要。
  3. 摘要不一致时不要安装，重新从可信发布页获取并检查。SHA-256 本身不能证明发布来源可信，校验文件也必须来自可信渠道。

Windows PowerShell

Get-FileHash -LiteralPath 'C:\下载目录\实际安装包文件名.exe' -Algorithm SHA256

macOS / Linux

# macOS
shasum -a 256 '/下载目录/实际安装包文件名.dmg'

# Linux
sha256sum '/下载目录/实际安装包文件名.AppImage'

上面的路径和文件名是示例，请替换为你实际下载的文件。命令只读取文件，不安装或运行安装包。

macOS TUN 辅助服务

“需要重新关联”表示系统服务登记与辅助程序启动状态需要核对：先停止代理，再在应用设置中重新关联辅助服务。“需要更新安装包”表示安装包签名或内容需要修复，请下载完整正式版本；重复授权不会修复签名。v0.7.18 已细分这些状态，实际可用版本仍以下载入口和正式发行记录为准。按原有 GitHub 流程生成的临时签名包没有 Developer ID 身份，TUN 仍未就绪；重复下载同一临时签名包不会补齐身份。项目更新签名与 Apple 签名、公证分开核验。

v0.7.19 先交付订阅卡片、导入处理、配置同步与自选节点功能；macOS 兼容包保留项目更新签名和完整性校验，未包含 Developer ID 或 Apple 公证，macOS TUN 本轮仍未就绪。安装检查失败显示“此安装包暂未满足 TUN 要求”，TUN 故障与原模式联网结果分开显示。后续正式签名、公证及实机 TUN 验收单独推进；最新可下载版本以下载入口和发行记录为准。

应用内更新签名

客户端的更新流程会校验更新包的项目签名；签名或校验失败时，应停止安装并保留错误信息。手动查看更新附件时，以 Release 中实际提供的签名文件和更新清单为准。

需要独立复核时，可查看仓库内的更新签名验证脚本及对应标签的配置公钥。务必使用与发行版一致的脚本和公钥，不接受陌生来源替换的密钥。

项目更新签名不是 Windows Authenticode 或 Apple 公证。没有看到发布说明中的明确证据时，不应假定安装包已完成系统级代码签名或公证，也不应自动绕过操作系统的安全提示。
