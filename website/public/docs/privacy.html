Know which system handles which data.

This website, the download center and the desktop proxy client are separate systems. Reading this website does not start a proxy or attach Codex.

What the website does—and does not do

The website serves static product information and documentation. It has no account system, analytics or advertising trackers, and does not ask you to upload subscription URLs, authentication tokens or local configuration. Platform selection, navigation menus and expandable answers change the current page state.

The homepage also queries this site’s public release-information API. Download routes ask the server to verify the latest formal release, package metadata and matching file availability before redirecting. Those requests do not require your proxy configuration.

Our scripts do not access your local proxy ports, start local services, launch the desktop client or change system settings. Product visuals are illustrative, not live connection monitoring. No third-party fonts, scripts or images are loaded by these documentation pages.

Only the theme preference is stored locally

The website stores only an appearance preference in your browser’s local storage under serylane-theme. The allowed values are dark, light and system. Dark is the default; system follows the browser’s operating-system color preference. If browser storage is unavailable or blocked, the website falls back without requiring storage access.

Our scripts never send this stored theme preference to the server, the download center or another service. It is used locally to render the website. It is not analytics or a desktop proxy setting.

Website scripts do not store a language preference, subscription, configuration, credentials or user profile, and do not set tracking cookies. Language is selected through the English and /zh/ page paths and equivalent-page links, not a saved language value. The desktop client’s own local files are a separate boundary described below.

Basic requests are still processed

Serving a page necessarily involves a request. Hosting and content-delivery services process basic access information such as IP address, request time, requested path and browser information for delivery and security. Choosing a language-specific URL also makes that requested path visible to the hosting service.

This is not a claim of “no data processing”. It is different from this website collecting proxy configuration, sending a stored theme choice, or the desktop client uploading subscriptions or model requests. Download services separately process requests for the files they deliver.

Download-center requests and external links

The website’s download service queries only public release metadata at the download center and checks the matching package on the center’s file domain. It does not forward the browser’s cookies, authorization headers or complete incoming request. Only a verified package of the same version and architecture is selected.

If verification is unavailable, the page reports failure and offers retry; it does not use an alternate source, an older version or another architecture. After a download redirect, the download center’s file domain delivers the installer and handles access data under its own service rules.

GitHub links are for source, change history, licenses and issue reporting only—not fallback product downloads. External destinations process requests under their own policies. Do not submit subscription URLs or tokens to unfamiliar sites. See download verification guidance.

Your desktop client and local routing are separate

You supply the desktop client’s subscriptions and proxy configuration. Subscription URLs can contain access credentials: review screenshots, logs and issue reports and remove tokens, full subscription links and personal information before sharing.

In the desktop client, AI-tool choices and custom domains are stored on your computer and compiled into domain rules. Domain routing is off by default; saving a draft is separate from confirming application. It does not decrypt TLS, rewrite model requests or create new Codex attachments.

Legacy attachment restoration checks ownership, preserves changes made by external programs and retains original backups. Subscription edits keep the original record, and the address is shown only when the edit form is deliberately opened. Program proxy and the old enhanced-stability strategy remain disabled. Read current routing behavior and limits.

Share a report, not a secret

Use the project issue tracker for ordinary reports. Public issues can be read by others: never paste passwords, private keys, subscription credentials or unredacted configuration.

For a security issue, first check whether the repository provides an appropriate private reporting channel. Do not disclose sensitive details on a public issue page.
