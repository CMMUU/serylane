# Serylane ユーザーガイド

インストールからサブスクリプションの取り込み、プロキシの選択、AI ツールの振り分け、更新とトラブル対応まで説明します。

## ダウンロードとインストール
<!-- anchor: install -->

[公式サイト](https://serylane.cmmuu.com/ja/#download)または[ダウンロードセンター](https://downloads.cmmuu.com/projects/serylane)で正式版を選びます。ノード、サブスクリプション、AI アカウントは付属しません。

- Windows：Intel または AMD の 64 ビット PC は x64、Arm 版 Windows は ARM64 を選びます。
- macOS：M シリーズは Apple シリコン、Intel 搭載 Mac は Intel を選びます。DMG を開き、アプリケーションフォルダーへ移します。macOS 13 以降が必要です。
- Linux：対応する AppImage に実行権限を付けて起動します。

## まず接続する
<!-- anchor: quick-start -->

1. 「サブスクリプション」で名前と Mihomo / Clash Meta 用の URL を入力し、検証して追加します。ローカル YAML はプロファイル画面で開き、検証して有効にします。
2. 使う設定が選択済みであることを確認します。設定を選んだだけではプロキシは起動しません。
3. 上部でシステムプロキシを有効にし、普段使うサイトを開きます。「接続」でリクエストがコアに届いたか確認します。

## プロキシモードを選ぶ
<!-- anchor: proxy-modes -->

- **システムプロキシ**は OS の設定を読むアプリ向けです。Linux でのシステム設定は GNOME の gsettings を使います。
- **TUN**はシステムプロキシを使わないアプリ向けです。macOS は署名・公証済みの完全版を使い、求められたら「ログイン項目と機能拡張」でヘルパーを許可します。Windows は試験的で管理者権限が必要です。Linux は未対応です。
- **ローカルポート**では `127.0.0.1` と設定の混合ポートをアプリに入力し、HTTP または SOCKS5 を選びます。制御ポートは使用しません。

ヘルパーの準備完了だけでは通信を取り込めたことになりません。有効なモードと実際の接続を確認します。

## サブスクリプションを管理する
<!-- anchor: subscriptions -->

カード単位または一括で更新できます。設定と使用量の更新は別々で、失敗時は最後に使えた設定が残ります。「その他」または右クリックで編集し、URL 変更後は更新を実行します。エラー時は、アカウントページではなく Mihomo 用 URL か、どのダウンロード経路で失敗したかを確認します。

## ノードの手動選択と AI プロキシ
<!-- anchor: nodes -->

手動ノード選択と AI プロキシは同時に有効にできません。手動ではグループ内のノードを選んで遅延を測れます。AI プロキシは条件を満たす 1〜10 ノードに対応し、1 つだけの場合は予備がありません。手動で適用してから適用済みの表示を確認し、必要に応じて自動選択に戻します。切り替えは以降の接続に適用されます。

## AI ツールのドメインと Codex
<!-- anchor: ai-tools -->

ドメインルーティングは既定でオフです。ルールモードでコアに入った接続だけが対象です。ツールやドメインと出口を選び、下書きを保存した後で有効化します。`example.com` はルート、`*.example.com` はサブドメインだけに一致します。[ルーティングの詳細](https://serylane.cmmuu.com/ja/docs/routing)を参照してください。

macOS または Windows の対応する Codex CLI は `codex --enable respect_system_proxy` で起動すると、その起動時だけ既存のシステムプロキシを読み取ります。PAC を有効化するコマンドではなく、フェイルオーバーも追加しません。[OpenAI の説明](https://learn.chatgpt.com/docs/enterprise/managed-configuration#use-the-system-proxy-for-native-client-requests)を確認し、実際のリクエストが完了するか試します。

## 更新する
<!-- anchor: updates -->

設定のソフトウェア更新でバージョンと実際の取得先を確認します。GitHub 直接、プロジェクトの高速化経由、起動中の Serylane プロキシ経由、ダウンロードセンターの順で試行します。同じバージョン・アーキテクチャと署名を検証します。古い内蔵更新が失敗したら、設定を残して対応する正式版インストーラーで上書きします。[検証の詳細](https://serylane.cmmuu.com/ja/docs/verification)。

## トラブルシューティング
<!-- anchor: troubleshooting -->

- アプリの接続が表示されない：ローカルポートのみでは通信を取り込みません。システムプロキシや TUN の状態を確認します。
- macOS TUN が承認待ち：ログイン項目を確認します。再関連付けが必要と表示されたら、先にプロキシを停止します。
- モード切替時にポート使用中：詳細を見て、停止直後なら接続が解放されてから再試行します。
- HTTP 401：AI のエンドポイントに到達した状態です。ログインと実際のモデルリクエストを別に確認します。

報告にはバージョン、OS、アーキテクチャ、モード、時刻と機密情報を除いたエラーを添えます。
